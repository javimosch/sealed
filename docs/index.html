sealed

A small self-hosted secrets store with limited agent tokens, built in machin.

Try it with a fake secretSource on GitHub

Experimental. No independent security audit. Not for production secrets.
It helps agents use secrets without accidentally exposing them. It does not stop an agent that is deliberately trying to get them.

what redaction does, and where it stops

# the command gets the secret; recognised forms are hidden in its output
$ sealed exec --env API_KEY=demo/api-key -- sh -c 'echo "key=$API_KEY"'
key=***

# the limit, in one line: transform the value and it gets through
$ sealed exec --env API_KEY=demo/api-key -- sh -c 'printf %s "$API_KEY" | rev'
0987654321-yek-ekaf

Ask for a secret without pasting it into chat

$ sealed request github/token --reason "to open pull requests"

The agent runs it. A desktop window says “Enter value for secret github/token”, you paste the value, and the agent only learns that it was stored. New secrets only; it never asks for your passphrase. It keeps the value out of the chat, not out of the agent’s reach: the same token can use it. Needs a desktop with GTK 3. The window has a “Show what I type” checkbox, off by default.

What it helps with

  • Out of the transcript

    Keeping keys out of chat transcripts, command arguments, shell history and logs.

  • Not in .env files

    Storing them encrypted instead of in .env files.

  • Scoped tokens

    Limiting a token to a group of secrets.

  • Approvals

    Asking you before a secret is replaced or deleted through sealed.

  • Audit

    Recording which token used what.

What it does not protect against

A token holder can get any value its token covers: by transforming it in exec, with render, or by calling the daemon directly. An agent running as your user can also read your token, which covers every secret. Root can read the daemon's memory. All the limits.

What it shows about machin

  • ~1,700lines of MFL
  • ~400lines of C
  • ~220 kBmain binary, stripped
  • ~23 kBwindow program, stripped

One program is both the command-line tool and the daemon. machin's built-ins provide Argon2id, AES-256-GCM, HKDF, HMAC, SQLite, sockets, an HTTP client and JSON. The main binary links dynamically to glibc, OpenSSL and SQLite, not GTK.

The desktop window is MFL too: about 200 lines calling GTK 3 directly, with no C file. machin has no FFI callbacks yet, so the program checks the window’s state itself every 20 ms. What you type never becomes an MFL string.

The main program is not all MFL. Hidden terminal input, running commands, redaction, temporary files, locked memory and process hardening are in a C shim. It is the most security-sensitive code, so review it first.

Try it with a fake secret

Linux x86_64, with machin (0.146.0 or later), a C compiler, and the SQLite and OpenSSL 3 development packages. The desktop windows also need the GTK 3 development files.

git clone https://github.com/javimosch/sealed
cd sealed
./scripts/demo.sh   # throwaway store; you choose a throwaway passphrase
